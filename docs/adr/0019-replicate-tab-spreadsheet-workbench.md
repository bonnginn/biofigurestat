# ADR 0019: データ入力を実験単位タブ付きスプレッドシートとして表示する

## 状況

条件を列、実験単位を行にして、各セルの中へ日付と複数のフォームを積み重ねる表示は、入力欄が大きくなり、WBや多条件実験で一覧性と入力速度が著しく低下する。生命科学の実験者はExcel、Googleスプレッドシート、ImageJ Resultsのような行列型の入力に慣れている。

一方、独立群の `実験単位1` を条件間で横に並べることは、統計上のpairingを意味してはならない。表示上の整理とcanonical designの対応関係を分離する必要がある。

## 決定

- データ入力ワークベンチは上部に `実験単位1 / 実験単位2 / ...` のタブを置く。
- 選択中のタブでは、条件を行、実験日と測定項目を列にしたスプレッドシート型グリッドを表示する。
- scalarでは `条件 / 実験日 / 測定値`、positive/totalでは `条件 / 実験日 / 陽性数 / 総数 / %`、source-preserving WBでは `条件 / 実験日 / 標的バンド / ローディングコントロール / 計算比` を基本列とする。
- 2処置の組み合わせも、flattenした全条件を同じグリッドの行に表示する。条件ラベルは入力済みfactor/levelから決定論的に生成する。
- 独立群の同じタブ番号は入力を整理するための位置にすぎない。別条件のunit IDは別々のままとし、pairing、blocking、analysis requestを変更しない。
- 対応のある測定では、1つのタブが明示された同一experimental unitを表す。日付はそのタブ内の全条件で同一とする。
- コピー＆ペースト、一括入力、キーボード移動はスプレッドシートUIの機能であり、raw observation、unit hierarchy、revision、analysis contractを変更しない。
- 保存・再編集では表示タブの選択状態ではなく、canonical unit ID、condition ID、outcome ID、experiment date、raw revisionをsource of truthとする。

## 結果

入力UIを変更しても既存プロジェクト形式や統計エンジンのmigrationは不要である。独立群を見た目上横に揃えることによる誤ったpaired解析を防ぐため、UIには「同じ番号は整理用であり、条件間の対応を意味しない」と明記し、保存テストでは条件間のunit IDが異なることを確認する。
