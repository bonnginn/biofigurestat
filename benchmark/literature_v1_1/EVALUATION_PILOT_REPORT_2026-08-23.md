# Literature benchmark v1.1 evaluation pilot report

## Outcome

Phase 1 passed and the JCB003 Track A/B smoke reached the real engine and produced all nine
artifacts. The planned 15-case × 2-track run was not started because the smoke exposed an artifact
capture reliability blocker: the Track A `default_graph.*` files are byte-identical to the edited
`final_graph.*` files even though the default capture event predates statistics and the final graph
contains a p-value annotation. The existing verifier accepted this inconsistent state because it
checks presence, identity and file validity, but not temporal fidelity of default versus final
captures.

Final recommendation: **REVIEW PIPELINE BEFORE FULL BENCHMARK**.

## Failure clusters

### Output/persistence: default graph provenance

- affected: JCB003 Track A smoke;
- frequency: 1/2 smoke runs exposed the contradiction;
- severity: High benchmark-infrastructure blocker;
- scientific impact: reviewers cannot reliably compare the untouched default with the finished
  graph, invalidating a required evaluation axis;
- workaround: none acceptable for autonomous scoring; external reconstruction would violate the
  artifact contract;
- A/B pattern: A exposed the issue after statistics annotation; B's unedited final graph remained
  identical to default, which is expected but cannot validate temporal capture;
- likely cause: the default snapshot lifecycle is not protected strongly enough against later graph
  state, and the verifier only checks existence/signatures.

No experimental-unit, pairing, nesting, time-identity, engine numerical or Track B leakage failure
was found in the smoke.

## UX findings

- Medium, Excessive interaction cost: eight experiment sessions must be created before the
  deterministic loader can be used, as required by the compatibility gate.
- Low, Terminology confusion: scalar per-cell literature values use the generic
  “強度・サイズ・形態” entrance.
- High, Output/persistence problem: default and final graph provenance cannot be trusted after an
  edit/statistics annotation.

## Priorities

1. Must fix before full 50×2: make the initial default graph snapshot immutable and add a regression
   test covering a later statistics annotation/edit.
2. Must fix before full 50×2: make the verifier validate temporal/default-final fidelity instead of
   only file presence and signatures.
3. Fix during benchmark-driven development: expose explicit capture timestamps or content hashes in
   `run.json`/the interaction log.
4. Later polish: reduce repeated session-entry interaction cost without letting the loader construct
   the scientific design.

No product fix was implemented during evaluation.
